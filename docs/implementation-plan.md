# 产线硅基工程师：完整实施计划

## 1. 目标、交付与模块结构

建设一个 Windows 本地运行的中文工程分析工作台，支持自然语言取数、现场问题调查、数据分析、曲线分析、图表制作、多会话、多轮对话及问题闭环。个人电脑使用模拟数据，迁移后连接公司允许使用的模型 API 和产线系统，Cursor 用于维护代码、适配已有程序和编写真实业务 skill。

### 交付物

- 完整模块化源码、中文界面、启动入口和配置示例。
- 五张关联表组成的模拟 MOS、模拟 Splunk 日志及模拟过程曲线。
- Skill 执行器、计划编排器、变量与产物仓库、错误恢复机制。
- 业务 skills，以及“产线 skill 编写”“现有 agent／工具迁移”两个开发 skill。
- Windows 离线安装包、接口文档、中文迁移手册和自动验收场景。

### 技术与运行边界

- Python 3.13＋FastAPI 后端，React／TypeScript 前端，SQLite 保存应用状态，Parquet 保存表格产物。
- 按 Windows 10／11 x64、普通用户权限、单人本机使用设计；服务只监听本机地址。
- 前端预构建后分发，日常运行无需 Node、Docker 或公网静态资源。Vite 支持生成这种静态资源包：[构建文档](https://vite.dev/guide/build.html)。
- 模型、MOS、Splunk 和图表程序通过适配器接入；真实连接失败不能自动切换为模拟结果。
- Python 使用项目独立环境；已有脚本可以配置自己的解释器，不覆盖已有 Python 环境。

### 模块边界

根目录只保留启动入口、说明和必要工程配置。主体代码按职责拆分：

| 模块 | 职责 |
| --- | --- |
| 编排器 | 意图路由、计划生成、确认、冻结、执行调度、问题覆盖检查 |
| Skill 运行时 | 技能发现、渐进披露、资源加载、内部执行循环 |
| 变量与产物仓库 | 数据、代码、SQL、图表、结论、版本及来源关系 |
| 执行器 | Python／脚本执行、超时、取消、日志、检查点和恢复 |
| 连接适配器 | 模型、MOS、Splunk、已有图表程序 |
| 分析模块 | 数据质量检查、统计计算、代表性预览、曲线处理 |
| 问题台账 | 问题、假设、证据、措施、验证结果和状态历史 |
| API 与前端 | 对话、计划确认、执行时间线、分析侧栏、问题管理 |

业务 skills、配置、模拟数据生成器、测试、迁移工具和文档分别管理。数据库字段、设备结构、工艺知识和批次规则不硬编码在编排器中。

## 2. 前端体验、多会话与多轮对话

### 视觉与工作区

采用“浅色精密工作台”：冷白背景、白色面板、石墨色正文和克制的蓝色强调；统一字体层级、间距、边框、圆角及图表配色。浅灰辅助内容保持清晰可读。

- 左侧会话列表、顶部会话标签、中间对话与执行时间线、右侧可调整宽度的分析面板。
- 图表、曲线和数据支持展开为大幅分析视图；表格支持分页、排序、筛选及大数据量下的虚拟滚动。
- 字体、图标、图表资源本地化，完整设计加载、空数据、等待确认、失败和恢复状态。
- 重点适配 1440／1920 宽度桌面屏幕，较窄窗口可收起侧栏；首版不增加双会话分屏。

### 执行时间线与文案规范

执行过程采用类似 Codex 的连续时间线，覆盖需求理解、计划准备、等待确认、查询、分析、修复和结果生成，状态来自真实执行事件。

**每一步默认显示一句完整的专业说明，同时交代分析目的和具体行动。** 不使用“我”“我们”等第一人称，不把内容拆成“目的：”“行动：”两个标签，也不将进度简化为只有“正在查询”一类缺少业务含义的短句。

文案信息量与语气参考：

- “为判断失效是否与开班后的生产状态有关，正在查询不良件的上线时间，并统计其在早晚班首小时内的分布。”
- “为验证可疑批次是否具有更高的不良风险，正在调取同期合格与不合格工件的数据，对比不同批次的不良率及压装力分布。”
- “为排查设备状态变化与失效增多之间的关系，正在检索该工站近两个月的相关变化点，并与不良率趋势进行对照。”

这些示例规定专业程度与信息完整性，不限定所有说明使用同一种句式。说明应结合当前问题、工站、数据或验证假设，自然表达本步为什么执行、具体执行什么。

每个步骤卡片包含默认可见的进度说明、真实状态，以及执行完成后的实际发现或受阻原因。技术细节以浅灰样式呈现并默认折叠，展开后可查看：

- 已读取的 skill、版本及具体参考资料。
- 工具调用参数、生成的 SQL 和 Python 代码。
- 变量名称、描述、版本、总行数及最多 40 行的数据预览。
- 执行日志、错误原因、修复内容和重试结果。
- 生成的图表及相关证据。

全量数据在分析侧栏分页查看或导出，不灌入聊天正文。失败和重试保留原始记录；未开始的行动不能标记为正在执行，未完成的查询不能提前显示发现。常规日志归入折叠详情，时间线主区域保留对调查有意义的进度变化。

面向用户的确认计划仍只描述业务动作和预期结果；内部架构、skill 名称、代码和工具参数放在执行详情中。

### 多会话

支持新建、重命名、搜索、置顶、归档、重新打开及多个标签同时打开。

- 会话独立保存消息、计划、变量、产物和执行状态。
- 切换或关闭标签不取消后台任务，停止任务使用独立操作。
- 单会话同时执行一个业务任务；不同会话可以并行，默认最多两个执行，其余排队，限制可配置。
- 会话列表和标签显示运行、待确认、受阻和完成状态。
- 技能目录、连接配置、工艺知识共享；临时变量、生成代码和工作目录按会话隔离。
- 跨会话复用数据通过用户明确指定的不可变快照完成，并保留来源，不共享可被双方重写的变量。
- 问题台账属于应用级资源，一个问题可关联多个会话；更新时绑定明确的问题编号。

### 多轮对话

会话记忆保存当前目标、区域／工站／时间条件、已批准计划、关键发现和变量引用，按需加载历史细节；摘要不能替代实际计划状态或证据。

支持“只看夜班”“把这个批次与其他批次比较”“刚才的图改成箱线图”等追问。指代需解析到具体变量或图表版本，有多个合理对象时再澄清。

执行中的追问按影响处理：

- 查询进度或解释已有结果：根据已提交证据回答，原计划继续。
- 修改调查范围：当前节点完成后暂停，生成修订计划并等待确认。
- 明确要求停止：取消任务并保留已有结果。
- 已完成调查后的新请求：重新判断是直接调用一个 skill，还是生成需要确认的新计划。

批准必须绑定会话、计划和版本；旧计划卡片或其他标签中的“OK”不能批准当前任务。

## 3. 编排、变量池与执行协议

### 路由、计划与 Skill 执行

- `skills` 和 `host_capabilities` 由注册表生成并作为变量提供；提示词只定义访问方式，不硬编码元数据集合。
- 问题分析请求先且只进入“问题分析一般思路”skill；普通单项请求可以直接执行一个 skill。
- 一份结构化 DAG 生成内部执行视图和用户业务视图，共享步骤 ID、依赖、预期产物和完成条件。
- 使用分阶段确认：先规律挖掘，再依据证据确认深入验证；未批准计划可通过多轮沟通修改。
- 批准后冻结计划版本、业务范围、节点、依赖、输出约定和技能资源版本，运行时校验执行范围。
- skill 内部的计算和工具级 DAG 直接执行；任何位置新形成的 skill 级计划都进入用户确认流程。
- 已批准范围内的 SQL 修正、代码调试和有限重试不反复确认；新增调查步骤或改变范围需修订计划。
- 阶段完成后检查原问题是否已回答；有缺口时提出补充计划或明确证据不足，不能绕过确认扩展调查。

Skill 按元数据、正文、references／scripts 三层渐进披露。包内可包含工具声明及可执行脚本；只加载当前工站、知识块或操作需要的资源。

### 变量池与 SDK

变量池由持久化索引和产物文件组成，不依赖单个内存字典。每个变量记录名称、描述、类型、版本、产生步骤、来源变量及版本、存储位置；表格另含行数、列结构和覆盖范围。

SQL、代码、图表、结论、错误和执行记录同样进入变量系统。生成代码通过稳定 SDK 读取和写入：

```python
nc = ctx.vars.load("nc_records")
bindings = ctx.vars.load("first_bindings")

ctx.vars.save(
    "nc_records",
    rewritten_data,
    description="补充首次零部件绑定信息后的 NC 明细",
)
```

执行器绑定实际读取版本；同名 rewrite 生成新版本并保留历史。计划通过步骤输出引用接收子 agent 自行命名的变量，后续节点不猜测名称。变量发布统一由宿主完成，防止失败代码留下半成品。

常用变量通过稳定入口提供，临时变量通过可检索目录动态加载。模型默认读取描述、结构和 preview，计算代码直接读取全量数据。

### 自动 preview

新增或重写表格自动生成 `{变量名}_preview`：

- 按各列不同值数量升序处理，优先覆盖低基数类别、去重选行，再补充固定种子的抽样。
- 通常最多 30 行，覆盖需要时扩展到 40 行；小表完整展示。
- 附带列类型、不同值数量、缺失情况和覆盖说明。
- 源数据与对应预览一致后才对模型发布；生成失败时明确标记不可用，不能将旧预览当作最新结果。
- preview 自身不再次触发 preview；代码、SQL、图表等变量使用相应摘要或附件展示。

### 公共接口、事件与恢复

统一定义技能清单、工具能力、计划、变量引用、执行结果和执行事件类型。前后端使用 REST 与事件流。

执行事件携带会话、轮次、任务、步骤、顺序号、状态、产物引用及用于展示的一句进度说明。内部可以分别保存业务目的和执行动作，以便生成准确文案；前端不渲染为两个固定标签。支持断线补发、去重和按会话分发。

同一会话内的所有 skill 共享工作目录和变量空间；代码在独立进程运行，支持取消、超时、子进程回收和检查点。SQL／代码默认最多自动修复两次，网络临时失败有限重试；超过限制后保留结果并明确受阻原因。

应用重启后从有效检查点恢复，不无故重跑成功节点，也不恢复用户已经停止的任务。Python 为默认执行能力，PowerShell 和 Bash 按宿主实际可用性注册。普通进程隔离不等同于强安全沙盒，执行器保留替换为公司隔离环境的接口。

## 4. 业务能力、模拟环境与迁移 Skills

### 业务技能与工具

| 技能或工具 | 首版内容 |
| --- | --- |
| 问题分析一般思路 | 明确问题、规律挖掘、假设、验证、结论与分阶段计划 |
| MOS 子 agent | 自然语言生成、校验并执行只读 SQL，实际结果写入变量池 |
| 数据分析 skill | Python 编写规范、全量变量读取、统计计算与证据输出 |
| preview 工具 | 根据变量名生成结构摘要和代表性预览 |
| 设备结构 skill | 按工站加载结构、功能、失效模式和检查方法 |
| process skill | task／parameter 映射、零件上线清单、BOM、PFMEA、CP、工艺流程 |
| rewrite skill | 数据关联与重写，检查关联键、行数、未匹配记录和来源 |
| Splunk skill | 包装已有 agent，查询绑定、变化点、质量参数、信号和操作日志 |
| 批次号解析 skill | 零件／供应商编码规则、样例及无法解析记录 |
| 图表制表 skill | 包装已有图表程序，提供本地默认实现和标准图表产物 |
| 曲线分析 skill | 叠加、对齐、特征提取、异常区段、分组比较、时间趋势 |
| 问题跟踪与报告 skill | 台账、证据、措施、验证结果及可导出的分析材料 |

MOS 的最小业务返回结构为：

```json
{
  "variable_name": "nc_records_station_a",
  "row_count": 128,
  "description": "指定区域、工站和时间范围内的 NC 明细，包含工件标识、发生时间、检测任务、参数及检测结果。"
}
```

变量版本和追溯信息由宿主补充。行数和数据来自实际执行结果，不能由模型推测。连接真实模型时，自然语言 SQL 必须由模型依据问题和 schema 生成，不能用预设 SQL 冒充通用取数能力。

### 问题调查流程

规律挖掘阶段覆盖所有指定方向：

1. 明确区域、工站和时间范围，查询 NC，区分不良工件数与 NC 事件数。
2. 检查开班集中、当班及前一班产量，以及异常长的过站间隔。
3. 将时间线扩展到一至两个月，同时观察 NC 数、检测量和不良率，区分突然升高与持续恶化。
4. 结合设备结构建立设备假设。
5. 从 process 找到 task／parameter 关联零件、PN 和上线工站。
6. 从 Splunk 获取首次绑定，按 TG 及必要的零件／安装位置维度补充数据，避免一对多关联放大 NC 行数。
7. 比较批次与供应商集中度，选择证据最明显的方向，同时记录其他方向的检查结果。

深入验证依据用户批准的计划执行：

- 批次方向：查询同期 OK 与 NC 全量数据，比较投入量、不良率、参数分布和曲线特征。
- 设备方向：查询相关结构近两个月变化点，形成现场检查或备件验证建议。
- 证据不足：明确缺口及下一步取证需求，不直接宣称排除设备或确认根因。

经验规则配置化。默认上海时区，07:00／19:00 换班，首小时为开班窗口；班产按配置出口工站的去重 TG 完成数统计。保留 `<5`、`<100`、`≥700`、过站间隔 `>4 小时`、NC 批次占比 `>80%` 等规则，区分线索、关联与已验证根因。100—699 件单列为未达正常产量阈值，不混入停产或验线分类。

没有找到设备资料或变化点时记录证据缺口，不据此直接排除设备或认定必须更换备件。NC 中批次集中度高需进一步比较同期投入量和不良率。

### 曲线分析、台账与导出

曲线提供压装力—位移、扭矩—角度两套示例配置，其他曲线通过配置扩展。保留原始曲线，支持起点／配置接触点对齐、公共区间重采样，以及峰值、峰值位置、斜率、终点、波动等特征提取。

支持按 OK／NC、批次、供应商、班次和变化前后分组，比较异常区段及特征分布。轴含义、单位和过程阶段必须一致；统计参考包络不能自动替代工艺规格。只有最终数值时进行趋势和分布分析，不还原不存在的过程曲线。

问题台账保存描述、关联会话、假设、证据、措施、责任人文本、期限、验证结果及状态历史。支持关闭和重新打开，关闭由用户确认。

支持 CSV／Excel 导入、表格导出及包含图表和证据链接的 HTML 报告。图表资源随报告本地化，支持离线查看。

### 模拟环境

模拟 MOS 严格使用五张业务表：工件、工站、过站记录、参数检测记录、NC 记录。五表通过工件、工站、过站和检测记录标识关联。

模拟 Splunk 日志和曲线文件单独保存，不增加 MOS 业务表数量。生成 90 天固定种子的可复现数据，覆盖正常班产、验线、停产、开班异常、长时间滞留、逐渐恶化、突然升高、真实批次问题及“NC 占比高但风险不高”的反例。

### 指导 Cursor 的开发 Skills

开发 skills 与工程师日常使用的业务技能库分开管理。

**产线 skill 编写 skill：**指导 Cursor 根据真实 schema 和工艺资料编写能力边界、触发描述、输入输出、变量约定、正文、references、scripts、工具声明和验收样例。提供数据库结构、工站知识、批次规则及工艺文件模板，附元数据、引用路径、工具依赖和变量输出校验器。未知字段与业务含义必须查证，不能臆造。

**agent／工具迁移 skill：**指导 Cursor 检查已有 Python 函数或脚本的入口、依赖、鉴权、返回值、日志和异常，再通过适配器复用。MOS 保留子 agent 身份，Splunk 以 skill 包装已有 agent，图表工具输出标准产物；脚本支持配置独立解释器。

模型提供默认 OpenAI 兼容聊天协议适配器及自定义 HTTP 适配接口。不要求供应商必须支持原生工具调用，普通文本中的结构化指令经过校验后也可执行。认证配置在工作电脑设置，不进入前端展示、代码示例或导出日志。

## 5. 离线交付、验收与实施顺序

### 离线迁移

离线包包含源码、预构建前端、锁定依赖、Windows x64 wheels、Python 用户级安装材料、模拟数据、初始化／启动脚本、校验清单及中文迁移文档。官方 Windows 安装器支持用户级和离线安装：[Python 文档](https://docs.python.org/3.13/using/windows.html)。

真实迁移集中修改公司模型配置、连接适配器、字段映射和知识文件，尽量不修改编排器、变量池及通用执行器。

### 验收标准

- **视觉与工作区：**使用真实模拟数据检查主要页面、长表格、曲线、折叠详情和各种状态，完成浏览器实测与截图检查。
- **进度文案：**每个业务步骤以一句专业说明同时表达目的和行动；不使用第一人称，不分列“目的／行动”，也不退化为只有动作的短句；句式允许自然变化。
- **过程可见性：**说明和状态默认可见，skill、参考资料、代码、数据默认折叠；状态来自真实事件，失败及重试可追溯。
- **会话与多轮：**验证并行任务、标签切换、追问引用、范围修改、旧版本批准、断线恢复和跨会话快照，禁止消息或数据串到其他会话。
- **计划与变量：**验证确认不可绕过、修改后必须重新批准、变量版本正确、preview 不陈旧，以及历史结果可追溯。
- **取数能力：**真实模型覆盖未预设提问、同义表达、多表 JOIN、追问修改、空结果、SQL 修复和重复计数问题。
- **业务正确性：**验证跨日班次、阈值边界、趋势分母、首次绑定、多安装位置、批次反例、单位冲突及曲线异常定位。
- **恢复与迁移：**验证模型超时、代码失败、取消、执行中重启、普通权限、中文路径和无公网安装启动。
- **演示与真实 AI 分开：**无 API 的确定性演示只验证流程；真实自然语言规划和 SQL 生成需另行通过模型接入验收，不能相互替代。

### 实施顺序

核心接口与变量池 → 模拟连接器 → 编排与 Skill 执行器 → 前端工作台、会话和执行时间线 → 业务分析、曲线与台账 → 开发 skills、离线包和端到端验收。

以上全部属于完整项目交付范围。
