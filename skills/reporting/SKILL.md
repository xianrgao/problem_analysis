# 分析报告

先查看批准计划完成情况、关键结论及证据目录，再调用 `report.create`。报告反映已经完成的工作，不把计划节点当作实际成果。

正文依次回答：发生了什么、影响多大、发现什么规律、什么证据支持候选原因、验证进展如何、下一步是什么。只有用户或现场记录证实执行后，才写“已更换”“已整改”等过去式。

## 输出要求

- 标明查询范围、时区、数据来源模式（模拟／真实）、版本和报告生成时间。
- 关键数值给出分母、去重粒度和单位；NC 频次、不良件数、不良率分开。
- 每个图表对应分析结论，注明源变量版本；可以从报告定位 SQL、代码或证据目录。
- 假设、相关性与已验证原因分开叙述；缺失日志、缺少对照或未执行验证作为限制说明。
- 所需图表脚本和资源本地化，HTML 可断网查看。导出全量数据是独立附件，不默认将全部记录嵌入报告。
- 报告内容经过 HTML 转义，日志或数据库文本不得变成可执行脚本。

报告生成失败保留证据产物并说明原因；不能返回一个不存在的下载链接。简短追问可直接回答，不必每次生成报告。
