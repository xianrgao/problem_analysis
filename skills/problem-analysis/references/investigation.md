# 调查手册

以下阈值是项目的演示默认值，运行时优先使用配置中的业务规则；迁移时需由产线工程师确认统计口径。

## 1. 确定问题与取得 NC

将用户问题整理为包含区域、工站、时间、task／parameter 的 MOS 请求，例如：“查询装配区 OP20 在 2026-09-10 07:00 至 2026-09-17 07:00 的 PRESS／peak_force NC 明细，包含 TG、检测值、单位、判定、发生时间、过站关联 ID 和上线时间。”使用实际业务字段映射，不据例子猜真实 schema。

MOS 结果需写入变量池并返回变量名、总行数和介绍数据范围及列语义的描述。空结果应保存零行数据与查询范围，不能补造 NC。

先统计：NC 事件数、去重不良 TG 数、覆盖时间、工站、task／parameter、缺失值及重复记录。一次工件多个 NC 不代表多个不良工件；返工与首次检测需要分层。

## 2. 开班、班产与滞留

- 时区使用配置，演示为 Asia/Shanghai。班次为当天 07:00–19:00、当天 19:00–次日 07:00；早于 07:00 的事件属于前一天夜班。
- 开班窗口 `[07:00,08:00)` 与 `[19:00,20:00)` 按工件上线时间判断，不使用 NC 发生时间替代上线时间。报告 NC 中的占比；若要判断风险增加，需对比同期全部上线件的比例。
- 对每个不良件所在班次及上一班，按指定出口工站去重 TG 统计班产。演示阈值 `<5` 为停产，`5–99` 为验线，`100–699` 为低于正常产量阈值，`≥700` 为正常范围。没有完整出口记录时不能将缺数解释为停产。
- 疑似滞留时查这些 TG 的完整过站记录，在生产顺序内比较相邻记录，输出间隔、上一站与下一站。`>4 小时` 作为长间隔线索；恰好 4 小时不满足。先识别返工回流和计划性离线，避免错误排序产生假滞留。
- 在班次缺失或首次过站之前没有记录时标记“不可判断”，不填零。将件级判定与班级产量分别保存。

## 3. 时间趋势与设备

将范围扩展至一至两个月，按同一 task／parameter 和相同判定规则比较每日／每班的 NC 数、投入／检测量和不良率。缺少检测分母时只报告频次趋势，不报告风险变化。

持续上升可提出设备退化假设；突然上升可检查变化点、来料、参数、环境及设备突发故障，不通过“突然发生”排除设备。加载对应工站设备 reference，将失效指标与结构的功能关系逐项映射，记录支持和反对证据。没有知识资料只能说明知识未覆盖，不能证明设备无问题。

## 4. 零件与首次绑定

在 process 中按 task／parameter 找到零件、PN、上线工站和安装位置，再查询 Splunk 的首次有效绑定事件。检索请求需含 TG 集合变量引用、零件／PN、绑定工站及时间范围；参考代理支持何种入参，不把上万 TG 粘贴进提示词。

首次绑定按 `(TG, component, position)` 取最早有效记录；不能按单一 TG 丢掉同件不同位置。需要区分返工改绑、解绑和日志重放。同一最早时间多条冲突绑定保留冲突并标记，不任意选择。

通过 rewrite 将每个指定零件／位置的绑定字段横向补充到 NC 明细；使用左关联保留原 NC 行，检查记录主键及行数没有被放大。共享变量的新版本应触发自动 preview。

读取 batch-analysis 编码规则，解析批次与供应商后，使用 data-analysis 计算集中度。以去重不良 TG 为基础，按零件及位置分别统计，列出无法解析与未绑定占比。超过 80% 显示“强集中线索”，不是根因确认。

## 5. 深入验证

批次线索：限定原 NC 的工站、task／parameter 和时间范围，拉取同期 OK 与 NC 全部检测及绑定，比较批次／供应商的投入量、不良率、参数分布与曲线。生产数量很大的批次即使占 90% NC，其不良风险仍可能低于其他批次。按必要因素分层，如班次、设备、产品型号、返工状态，避免混杂。

设备线索：按怀疑结构查询最近两个月的维护、换型、参数修改、备件更换、报警等变化点，与失效率及参数趋势对齐。没有变化点时，说明日志覆盖并提出现场测量、点检、备件对照或受控更换建议；实际操作遵守企业流程，不由系统自动实施。

验证动作应包含假设、对照、观察指标、预期结果和停止条件。若数据同时支持多个原因，保留多个假设，优先选择信息增益较高且现场可执行的验证。
