# 查询口径与输出约定

## 首次绑定

确认“首次”的含义是首次有效装配，还是检测时点有效装配。问题初步调查默认前者。将大规模 TG 查询交给适配器分批处理，并统一去重、时间排序、分页完成状态。

原始键为 `(tg, component, position)`，不可只保留单 TG 首条。时间相同且内容不同为冲突；改绑和日志重复需要根据事件语义处理。输出足够字段供 rewrite 验证，不在检索层静默丢失冲突。

演示绑定列：`tg, component, pn, position, batch, supplier, bound_at, event_id`。使用真实模式时，schema 与字段映射需来自真实系统检查结果。

## 变化点

范围默认为经批准的最近两个月，条件含工站及具体设备结构。维护、更换、程序版本、参数修改、换型、传感器标定、报警处理是不同事件类型，应保留类型而非合并成无法区分的文本。

变化点在时间上先于不良率上升仅提供线索；必须考虑检测量、停机后恢复、班次和来料变化。未命中关键词不能证明没有变更，需注明检索字段及覆盖。

## 参数、信号和操作

明确日志时间与设备时间的区别，保存单位、采样频率／事件触发方式及工件关联能力。仅有站级信号时不能硬关联某一个 TG。高频日志先通过代码端过滤与分段，模型查看结构预览与摘要。

## 部分结果与失败

超时、分页失败、权限不足、结果截断分别返回可识别状态。部分结果可保存并标记 `partial`，描述缺失的页／时间段，但不得被后续不良率运算当完整总体。重试不应重复发布相同行或重复计入事件。
