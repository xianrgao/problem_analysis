# 问题跟踪

台账属于应用，调查变量属于会话。更新前确定唯一问题 ID；多个可能问题时澄清，不能把当前会话最新问题视为任意更新对象。

通过 `issue.update(issue_id, fields)` 更新宿主支持的字段，记录标题、描述、工站、状态、责任人文本、期限、假设、证据、措施及验证。状态以当前 API 能力为准，不自行创建不存在的状态枚举。

证据引用具体会话、变量和版本。描述应区分“建议措施”“现场已执行措施”“验证结果”；数据分析完成不等于维修或验证已执行。外部负责人只是记录，不自动发送消息或分派外部系统任务。

## 变更要求

- 创建：写清问题现象、影响范围与当前调查状态；没有确定责任人或期限就保持未指定。
- 更新：只改用户指定或本轮明确产生的事实，保留已有证据和状态历史。
- 措施：包含待执行动作、责任人、计划日期、实际执行日期、验证指标；未知日期不猜测。
- 关闭：先给出证据与未解决事项，只有用户明确确认关闭后才提交关闭状态。模型认为调查结束不能代替确认。
- 重新打开：保留历史关闭记录，说明新增证据或复发原因。

不要在台账里复制全量生产数据；用变量快照与报告链接让后续工程师定位证据。记录解释不确定性和待补数据，避免交接时把假设误作既定根因。
